### What actually changed in the lockfile

Decoded from the two byte arrays in the job log (the assertion prints `Vec<u8>`, not text):

```diff

  # It is not intended for manual editing.
  version = 4

  [[package]]
  name = "lockfix"
  version = "0.1.0"
+
+ [[patch.unused]]
+ name = "pmat"
+ version = "3.41.0"
```

### Five whys

1. **Why did `cpu-gates` fail?** GATE B2 ran 21776 lib tests and 2 failed — both compare a
   fixture `Cargo.lock` before and after `pmat analyze dead-code`.
2. **Why was the lockfile not byte-identical?** `cargo` appended
   `[[patch.unused]] name = "pmat" version = "3.41.0"` to it.
3. **Why did cargo record an unused patch?** A `[patch.crates-io]` table naming every
   workspace member of the tree under test is in scope for that cargo invocation, and cargo
   writes patches it did not use into the lockfile it produces. The fixture crate has no
   dependencies, so the pmat patch is unused.
4. **Why is that table in scope inside a throwaway temp crate?** Because paiml/infra
   installs it in `$CARGO_HOME/config.toml` **on purpose** — `gates-lib.sh`
   `_cr_install_inheritable_overlay` (infra#653): *"the overlay is ALSO installed where
   every child cargo inherits it, whatever its cwd or manifest path"*. `--config` covers one
   process, not the process tree; that was measured on aprender v0.68.1 (run 35241651945),
   where a child `cargo metadata` in a test missed the overlay and failed. pmat's analyzer is
   exactly such a child: it shells out to `cargo check` inside the analysed directory.
5. **Why did this only surface on this tag?** Two independent reasons, both dated today, and
   neither of them anything in the 3.41.0 diff:
   - `gate / cpu-gates` was **timeout-killed at 30 min on every tag since v3.39.0** (#1358), so
     **GATE B2 had never once run to completion in CI**. paiml/.github#72 raised the limit to
     90 min today; this run reached 62 min and got a verdict for the first time.
   - The `--locked` flag that made cargo *refuse* rather than write was **reverted on
     2026-08-25** (`2bdc6b90c`) because it silently disabled the compiler scan. **#1076 is
     still OPEN**, and these two tests are the spec written for its real fix. The tests
     themselves date from 2026-08-25 — they are not new in this release.

**Owner: split, and the pmat half is user-visible.** `CargoDeadCodeAnalyzer` does not isolate
its nested `cargo check` from ambient cargo configuration, so **any user with a
`[patch.crates-io]` in `$CARGO_HOME/config.toml` will have their project's `Cargo.lock`
rewritten by `pmat analyze dead-code`** — which is the class of defect #1076 exists for.
Filed independently by the operator as **#1403** at 00:24:33Z, one minute after the job
failed, with the same mechanism. No ticket was filed by this session: the defect was already
ticketed, and an un-rowed issue reds CB-2115 on every open PR.
